SK텔레콤 · 2025.04 – 2025.10

에이닷 일정 에이전트

역할 · 에이전트 설계 및 개발

2.5×일정 MAU 성장20.3만 → 51.1만 (2025.01 → 2025.09)
67%에이전트 경유 등록일정 등록 9.8만 건 중 6.6만 건

01배경 및 목표

  • 에이닷의 일정과 알림을 대화로 처리하는 에이전트를 만들었습니다.
  • "내일 3시 치과 넣고, 금요일 회의 30분 미뤄줘"처럼 여러 의도가 섞인 복합 발화를 빠르고 정확하게 처리하는 것이 목표였습니다.

02핵심 과제

  • C1 복합 발화 처리와 응답 속도
  • C2 외부 일정(Outlook·Google Calendar)과 구독 일정 연동
  • C3 반복 일정·알림 등 시간 정보의 정확한 처리

03기여 내용

"Plan-and-Execute" 패턴과 "Refine" 단계를 적용한 에이전트 아키텍처C1
  1. Plan: 사용자의 요청을 하위 작업(Sub-Task)으로 나누고 작업 간 순서를 부여
  2. Execute(순차): 순서가 있는 하위 작업은 차례대로 끝까지 실행
  3. Execute(병렬): 서로 영향을 주지 않는 하위 작업은 병렬로 실행해 응답 속도 향상
  4. Refine: 실행 결과를 바탕으로 재계획(Re-planning)해 작업 정확도 향상
외부 일정·구독 일정 연동 설계C2
  1. 외부 일정(Outlook, Google Calendar)과 구독 캘린더(혜택·이벤트 일정)를 LLM이 구분해 연동 여부와 조회·변경·삭제 가능 여부를 판단하도록 설계
일정 추출 RAG 설계C1
  1. 필터링: 일정 관리 주체, 구독 여부, 조회 일자 등으로 후보 일정 도출
  2. 병렬 검색: 후보 일정을 N개로 나누고 LLM을 병렬로 호출해 제한 응답 시간 내에 요청한 일정 추출
  3. 검증: 추출한 일정이 요청에 해당하는지 판단하고 근거를 함께 추출해 정확도 향상
시간 정보 처리를 위한 프롬프트 엔지니어링C3
  1. 반복 일정과 알림을 정확히 다루도록, 일정 국제 표준(iCalendar)과 ISO 8601 기간 표기를 쓰게 프롬프트 설계

04기술 스택

프레임워크 · 플랫폼
LangGraph, Gradio, FastAPI
방법론
Prompt Engineering, RAG, Plan-and-Execute

05성과

  • 일정 등록의 67%가 에이전트 경유 (에이전트 6.6만 건 / 전체 9.8만 건)
  • 서비스 전체 일정 기능 MAU 2.5배 성장 (2025.01 20.3만 → 2025.09 51.1만)

연락처

사람의 판단을 돕는 에이전트, 함께 만들어요.
